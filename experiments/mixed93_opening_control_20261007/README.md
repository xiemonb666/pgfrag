# Mixed93 opening-controlled cohesive history

This source package defines a bounded, fixed-face Mode-I history diagnostic for the saved 93-DOF case. It reuses the completed elastic bridge result as JSON input. The driver reconstructs each jump operator as `J_i = Hplus_i - Hminus_i`, checks the saved normal row against `alpha_i = 2*sqrt(-x_i/R)`, and imports only the pinned enriched cohesive trace primitive. It makes no new MLS/provider calls and never opens an NPZ.

The elastic response is computed once by a 100-by-100 bulk/gauge/opening KKT solve with zero physical body and boundary forces, zero physical gauge target, and `e82 dot q = 1`. The resulting vector `v` is scaled as `q = Q*v`; the six physical gauge multipliers scale by the same `Q`. Before the history loop, the driver verifies every unit-response point has the analytic normal opening and zero tangential jump within the declared tolerance. Any mismatch fails the run without projecting or editing the trace.

The 12 prescribed opening levels are `[0, .05, .15, .30, .12, .30, .50, .75, 1.10, .65, 0, 1.10] * Qstar`, where `Qstar = deltaf/min(alpha_i)`. The first peak takes all quadrature points past full damage. The `.30 -> .12 -> .30` segment unloads and reloads while some quadrature points retain partial damage. The last segment unloads fully damaged points to zero and reloads them. Committed primitive states are carried forward at every step.

The reported applied control force is positive in the opening direction and equals `(K*q + C_phys.T*lambda_phys + f_gamma)[82]`; all other generalized-force entries must remain numerically zero. For each interval, bulk work uses the exact quadratic energy difference. Cohesive work is independently integrated from the declared bilinear law using the previous committed opening, maximum opening, and damage. The driver compares that value with the area-weighted change in the primitive's cumulative external work, then checks total work against the change in bulk stored, cohesive stored, and cohesive dissipated energy. It does not estimate interval work with a trapezoid across law corners.

At `Q=0`, the primitive's tangent status and reasons are recorded as a corner observation; the tangent is not projected or used in a solve. The JSON result preserves the saved raw `K`, physical `C`, rigid candidates, reconstructed face operators, unit response and multipliers, each point's force and law branch, each trajectory state, and little-endian float64 history bytes for displacement, damage, opening, and maximum opening.

The numeric path is disabled in `SOURCE_PINS.json` until a separate root-go token is supplied. The frozen run limits are one KKT solve, 12 primitive assemblies, 20 seconds, 8 MiB of result output, no retries, and no provider calls. This remains a toy fixed-face diagnostic: it does not model growth, qualify a real material, or support roughness or multibody conclusions.
