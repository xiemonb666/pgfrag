# Explicit crack-surface state candidate

This is a source-only, isolated mechanics-coupled branch kernel for review. It is not imported by `pgfrag`, does not modify the production runner or vendor solver, and does not write to `observedfeatures`.

The state stores one authoritative material/reference-space triangle mesh per patch, its oriented boundary edges, a stable surface ID, creation step, and optional parent patch. The negative and positive sides reference that same geometry and use independently stored displacement arrays; exported side triangles reverse winding. Inputs must be exact `numpy.ndarray` objects; array-like conversion hooks and ndarray subclasses are rejected. Shape and row caps are checked before dtype conversion, contiguous copying, or byte serialization. Arrays are then copied onto immutable byte buffers. Duplicate/degenerate triangles, inconsistent winding, and nonmanifold edges fail closed. A multi-loop, touching, branched, or explicitly uncertain boundary remains `UNKNOWN_UNSUPPORTED_BRANCH_OR_INTERSECTION`; global patch intersections remain `UNKNOWN_NOT_EVALUATED`.

Patch assignments bind one exact patch ID to one exact pair of fixture fragment/body IDs. A relation entry is assigned fixture metadata inside the proxy namespace; it does not verify that two fragment geometries share a physical surface or establish geometric/model R2. Its positive area is the stored patch's reference area, not an independently verified common-boundary measurement. A fixture relation entry is recorded only for positive stored patch area, distinct body IDs, distinct fragment IDs, and a boundary whose directed edges form one oriented cycle. Internal cracks whose sides still belong to the same body do not create a relation. Later split patches must name a parent ID, and current relations are emitted only for assigned leaf patch IDs. No descendant Cartesian product is generated. Historical fixture relations are immutable with respect to current visibility/wear; visible compatibility is returned separately.

The bounded source contract caps each patch at 100,000 reference vertices and 200,000 triangles, each state at 4,096 patches and 256 MiB of stored arrays, and assignment/history ledgers at 100,000 rows each. These are memory guards for this candidate, not solver-resolution recommendations.

Every instance is fixed to namespace `fixture_proxy.explicit_surface_state.v1`, relation namespace `fixture_proxy_relation.explicit_surface_state.v1`, `mechanics_qualification=NOT_COUPLED`, and `mechanically_active=false`. This candidate has no external solver receipt verifier, so it cannot claim `SIMULATED_GEOMETRIC_GT` or production/model R2. Its `R2` relation kind exists only inside the fixture proxy namespace. Counts describe stored fixture geometry and never prove mechanics. The module contains no path to consume OSB-derived surfaces and no production promotion method.

The `SUPPORTED_SINGLE_ORIENTED_BOUNDARY_LOOP_TOPOLOGY` status means only that the patch's directed boundary edges compose one oriented cycle. It does not certify a global crack front, surface-surface nonintersection, or supported junction behavior. Parent IDs establish metadata lineage only: child-patch geometry containment in the parent, patch partition, and leaf-patch geometric lineage remain `UNKNOWN` and are not verified. This small state kernel does not check partition volumes, contact, energy balance, a fracture criterion, or the required solver consumers (displacement discontinuity, support visibility, and fracture evolution). It is not an Ai–Augarde implementation and does not infer or fit a surface from OSB damage.

`test_explicit_surface_state.py` contains counterexample-focused tests for exact ndarray inputs, fake `__array__` rejection, pre-copy zero-stride budgets, immutability, duplicate and degenerate faces, nonmanifold edges, touching-front ambiguity, side winding, same-body internal cracks, positive-area proxy pairing, historical wear behavior, strict descendant assignment lineage, schema/label leakage, and unknown topology. Tests and solvers were not run for this source review.
