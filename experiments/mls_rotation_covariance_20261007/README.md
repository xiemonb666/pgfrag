# MLS rotation and unit covariance prerequisite

This small check invokes the pinned `mls3d_shape.shape_functions_3d` provider directly on the accepted 27-site 3-D source product grid and the 16 interface quadrature points already defined by the mixed93 cohesive bridge case. It compares actual provider shape weights and physical gradients under one proper oblique rotation plus translation, and under uniform conversion from metres to millimetres. A fourth call is a negative control that applies anisotropic coordinate scaling while leaving the scalar MLS length parameters untouched.

For a proper rigid transform, the coordinates and `reference_origin` change by `x' = R x + t`; the scalar `reference_scale` and `support_radius` stay in metres. Distances, Wendland weights, and the normalized linear basis are invariant, so the MLS weights should agree. The reported gradient is with respect to the physical query coordinates and obeys `grad' = R grad`. The check compares that identity using the provider's actual returned arrays.

For the unit variant, all length-valued geometry inputs and both MLS length parameters are multiplied by 1000. This preserves dimensionless normalized coordinates and support ratios. The provider's gradient is then per millimetre, so the record multiplies it by 1000 before comparing in inverse metres. This geometry-only provider has no material parameter; the check does not rescale or otherwise change `E`, `nu`, cohesive properties, or any material data. Do not scale only point coordinates while leaving `reference_scale` or support radius in metres.

The anisotropic control deliberately changes geometry while retaining scalar `reference_scale` and `support_radius`; it is expected to change actual MLS weights and confirms that the test can detect a non-covariant transform. It is not an alternate physical model.

The intended future tests are: (1) proper non-axis rotation and a 64-query budget, (2) all 16 rows remain `OK`, have all 27 sources in support, and satisfy the frozen `1e12` condition ceiling, (3) rotated weights/gradients satisfy the covariance identities to `1e-10` in normalized gradient units, (4) mm and m weights and converted gradients agree to that tolerance, and (5) the anisotropic negative control changes weights by more than `1e-8`. The tests are source-only in this review; they must not be run until separately authorized.

This establishes only coordinate covariance for the supplied piecewise-linear source/query data and the pinned MLS provider. It does not run a solver, construct a fracture surface, measure tetrahedral discretization error, or establish that any real crack or mesh-direction bias has been resolved. Even a future pass remains `GIVEN_SOURCE_GRID_AND_INTERFACE_QUADRATURE_ONLY_NOT_ADMITTED`.
