# Bounded native contact spike

This experiment exercises the local Peridynamics.jl `MultibodySetup` and `contact!` API with two 4 mm cubes represented by eight 2 mm-spaced points each. It uses the standalone Julia 1.10.12 runtime and the existing `pgfrag/src/pgfrag/resources/julia` project, whose manifest resolves the read-only local headless fork at version `0.5.4+pgfrag.1`.

Run `run_contact_spike.ps1` from PowerShell. It fixes one Julia thread and first runs a gated, one-step native `MultibodySetup/contact!` interface preflight. The three fixed cases start only if this preflight completes and writes its actual state/metric CSVs and summary. The cases are a no-contact control and native contact at `0.5` and `0.25` times the raw native BB bond bound, for 240 and 480 steps respectively. All three have the same final time. The native BB bound does not establish penalty-contact stability.

The case CSV records actual positions, velocities, masses, native `b_int` total captured immediately after native Verlet contact, and a diagnostic BB-only `b_int`; their difference is the native contact force-density increment. The diagnostic snapshots/restores native arrays and asserts positions, velocities, acceleration, bond activity and other storage are unchanged. Point force is the contact increment multiplied by the point's own volume. Step impulse uses the trapezoidal native force samples, with initial contact force zero, and is compared with each body's momentum change. Contact potential energy is unavailable and total energy remains `UNKNOWN`. The experiment models discrete point-to-point cross-body contact; it does not reconstruct CAD surfaces, display a crack, or test fragment self-contact.

The runner checks each predicted Verlet position update for a finite, positive cross-body distance before entering native contact evaluation. Each case is capped at 128 points, 500 steps, one thread and 120 seconds. If the data export path blocks, the CSVs are appended during integration so saved progress remains reviewable.
