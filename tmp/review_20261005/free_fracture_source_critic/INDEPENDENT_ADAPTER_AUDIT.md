## Mechanics and reconstruction checks

- **Binary layout:** The adapter decodes the little-endian point tensor as `reshape((n_states, n_points, 21)).transpose(2, 1, 0)` and graph labels as `reshape((n_states, n_points)).T` ([adapter lines 661–676]). This is the inverse of the driver's Julia column-major, field-fastest frame writer and point-fastest-per-state label writer ([driver lines 424–487, 492–522]). Exact element counts, sidecar shapes, units, field names, byte counts, digests, finiteness, and ordered point IDs are checked.
- **Native event order and chronology:** The adapter requires strictly increasing `(step, point_i, point_j)` event order, unique first-break rows, and reciprocal active-to-inactive fields ([adapter lines 808–841]). The frozen driver sorts canonical pairs by point IDs and scans that roster in order at each captured state before writing events in insertion order ([driver lines 125–166, 290–320, 538–546]). Coordinates independently reconstruct each active bond's stretch; omitted robust threshold crossings, unsupported events, duplicate breaks, reactivation, per-point degree/damage discrepancies, and cumulative event/active-pair mismatches halt the audit ([adapter lines 886–1069]).
- **Components and completeness:** Union-find initializes every point ID, unions only active canonical pairs, and labels isolated points as singleton components using each component's minimum point ID ([adapter lines 498–558]). It compares all points and all states to the binary labels; the final optimization reuses a partition only when no first-break event changes the active roster, while refreshing selected-state bounds ([adapter lines 981–1000, 1036–1057]). Component counts remain explicitly graph diagnostics, not physical-fragment truth.
- **Velocity and energy:** `full_v` and `vhalf` retain distinct state fields. The adapter checks the native grip's half-step secant, free-DOF half-step update, position drift, full-velocity reconstruction, force-density/acceleration relation, and momentum update. Raw kinetic energy is calculated from stored full-step velocity and split into all, free, and grip-masked DOFs; the report leaves physical grip kinetic energy unknown ([adapter lines 1110–1171, 1220–1307, 1528–1545]). The final source uses point-axis masks for the discrete grip work calculation (`work_by_dof[left_mask, :, :]` and right equivalent, lines 1185–1189); this corrects the prior axis-indexing exception.
- **Grip association and claims:** The adapter reconstructs left/right masks from the analytic end layers, checks prescribed displacement and half-step secant, tracks every right-grip component membership, and separately counts grip-incident and cross-layer events. It labels these as active-graph associations and keeps physical crack surfaces/fragments, calibration, grid/horizon bias, and fracture dissipation unqualified ([adapter lines 723–757, 1131–1157, 1347–1425, 1533–1542]).

## Receipt bookkeeping and run-bound limits

The immutable completed launcher receipt reports `final_attempt_bytes = 88,924,215`; the actual tree, including its final receipt, is 88,924,268 bytes. The exact difference is **+53 bytes**. The pinned launcher records a size before its final receipt rewrite, then remeasures the post-rewrite tree only to decide whether the cap was exceeded ([`run_once.ps1` lines 362–384]). The receipt itself is unchanged and its SHA-256 matches the pre-audit inventory.

The final adapter records `receipt_final_attempt_bytes_match` as a zero-tolerance failed check, independently verifies the actual attempt tree against the case's `max_attempt_bytes` and the result tree against `max_output_bytes`, then continues only if the remaining receipt/source/hash/cap gates pass ([adapter lines 367–391]). The status is `AUDITED_WITH_RECEIPT_SIZE_DISCREPANCY` only when that is the sole failed check, and `native_arithmetic_validation` is reported separately ([adapter lines 131–175, 1456–1544]). Thus the expected eventual disposition is explicitly not ordinary `PASS`; callers should read the status field as well as the wrapper's exit code.

No current-run output-size blocker remains: the native point tensor is 73,332,000 bytes, graph-label tensor 1,746,000 bytes, event CSV 957,282 bytes, and the whole result tree is under 89 MB. One residual capacity limitation is that event CSV parsing materializes all rows before constructing the parsed event records ([adapter lines 732–764]). The disk cap bounds the input bytes but does not itself bound peak Python memory at a worst-case event count. This is not a blocker for the frozen input inventory, whose event CSV is under 1 MB, but a larger future case should use streaming or an explicit event/memory ceiling.
